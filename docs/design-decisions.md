# 核心设计决策

> 这套桌面套件是被真实生产环境逼出来的，以下每个决策都对应一个具体约束，不是纸上谈兵。

## 1. 用 Electron 桌面端，而不是 Web 服务

- **约束**：一线是单机常驻场景——门店与营运同事要"双击即用"，不想部署、不想登录、不想配环境。
- **决策**：Electron 桌面端，进程内嵌后端服务 + 单实例锁 + 空闲端口探测，用户零感知。
- **取舍**：放弃 Web 的跨平台即开即用，换来零部署、免鉴权、本地常驻。

## 2. 单实例锁 + 空闲端口探测

- **约束**：后端内嵌在主进程，重复打开会端口冲突、多实例打架。
- **决策**：单实例锁保证只跑一个实例；空闲端口探测避免写死端口撞车。
- **价值**：用户怎么双击都不会把应用搞崩。

## 3. 进程内嵌 Node 后端，而不是独立服务

- **约束**：没有运维、没有服务器预算，要"一个安装包全带走"。
- **决策**：Node 后端作为子进程内嵌进 Electron，数据本地落盘。
- **取舍**：牺牲分布式能力，换来零依赖部署——对单机场景这是对的。

## 4. 经营数据"次日自动生成分析"

- **约束**：原来人工采集 → 汇总 → 制表 → 打印传阅，慢一天且易错。
- **决策**：次日自动拉取全量门店数据，生成经营总览 KPI、AI 经营分析、异常雷达、30 日趋势，替代全人工流程。
- **价值**：高层与营运部打开就看到结果，不等人、不传错。

## 5. 黑金主题 + 配置化服务管理

- **约束**：给高层和营运看的驾驶舱要专业沉稳；运维工作台要能管一堆本地常驻服务。
- **决策**：统一黑金视觉体系；运维工作台把服务启停、健康检查、配置做成一键管控。
- **价值**：一个控制台管住所有本地服务，不用记命令、不用开一堆终端。

---

> **诚实边界**：以上为通用化、脱敏后的设计决策描述。生产实现含内部经营数据与私有服务配置，源码不对外开源。
